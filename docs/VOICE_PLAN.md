# Voice overhaul plan (Phases 62–67)

## Context

Live voice is not usable (user test, 2026-10-28):

- Browser STT mode: no words picked up, no barge-in, erratic.
- Server STT mode: the start of each sentence is trimmed ("One hundred twenty dollars" →
  "20$"), the agent's own voice comes back as phantom rep lines ("and payment, payment…"),
  the agent cuts itself off, and replies arrive about 3.5 s after the rep stops
  (`vad_end_to_first_audio_ms` in the audit log).

Root cause is the architecture, not one bug:

| Piece | Today | Why it fails |
|---|---|---|
| Agent voice | Browser `speechSynthesis` | Not an echo-cancellation reference in Chrome, so the agent hears itself; no timing, unreliable end events |
| Turn ends and barge-in | vad-web in the browser, silence only | Every echo workaround (guards, "contaminated" clips, VAD resets) also eats real speech, which is how onsets get trimmed |
| STT | Groq Whisper on each finished clip | Batch, not streaming; hallucinates on noise; adds latency |
| Two STT modes | `webkitSpeechRecognition` and server | Double the code paths, both fragile |

Target: behave like production voice agents (ChatGPT voice, LiveKit, Pipecat, Vapi):
- audio both ways over WebRTC, so browser echo cancellation works with laptop speakers;
- streaming STT with model-based end-of-turn detection;
- streaming server-side TTS;
- interruptions decided on the server with knowledge of exactly what the rep heard;
- end of speech → first agent audio p50 ≤ 1.2 s on fast-path turns, ≤ 2.0 s with LLM NLU,
  p95 ≤ 3.0 s.

What does **not** change: code decides every move, the engine computes every number, the LLM
only reads and phrases, spoken numbers come only from `Fact.render()`, and the rollback of
unheard turns from Phase 56 stays the rule for what the rep heard.

## Decisions (user, 2026-10-28)

1. **Providers: Deepgram only.** Flux for streaming STT with built-in end-of-turn
   (`eot_threshold`, `eager_eot_threshold`), Aura-2 for streaming TTS. One key; $200 free
   credit. Rough cost: Flux about $0.0065 per minute, Aura-2 $0.030 per 1,000 characters.
2. **Framework: Pipecat** inside the FastAPI app. Our `Orchestrator` becomes one custom
   `FrameProcessor` (final transcript in, sentences out). Pipecat supplies the WebRTC
   transport (`SmallWebRTCTransport`), the Deepgram services, interruption handling and
   metrics.
3. **Hosting: free TURN** (Cloudflare Realtime TURN: 1,000 GB a month free, short-lived
   credentials generated by our server) so WebRTC works on Render.
4. **Phase 56:** merged without its browser voice tuning (reverted); the server-side Whisper
   filter, stale-speech fix, unheard-turn rollback and fragment merge stay.

## Architecture

```
Browser                                   Server (FastAPI + Pipecat)
-------                                   --------------------------
mic (echoCancellation, noiseSuppression)  SmallWebRTCTransport (audio in/out)
  └─ WebRTC audio ───────────────────────►  DeepgramFluxSTTService (stream, EndOfTurn,
                                             EagerEndOfTurn, TurnResumed, StartOfTurn)
remote <audio> (AEC reference) ◄───────── │  OrchestratorProcessor (ours)
                                           │    final transcript → Orchestrator.on_creditor_text
existing WebSocket /ws/call/{id}  ◄──────►  │    Utterance sentences → TTS, one TTSSpeakFrame each
  (UI events unchanged: transcript, say,   │  DeepgramTTSService (Aura-2, streaming, Clear on barge)
   turn_trace, belief, phase, errors)      │  output transport: tracks what was actually played
                                           └─ HeardTracker: played sentences → on_sentence_done;
                                              interruption → on_barge_in(spoken_ids) → rollback
```

- **Two channels, one call id.** WebRTC carries audio only. The existing WebSocket keeps
  every UI event and the text mode, so the console, traces and schema stay as they are.
  Voice is an option on a call, joined by `call_id`.
- **What was heard.** A sentence is heard once its audio has finished playing on the output
  transport (Pipecat pushes text frames in step with playback). On interruption, the
  sentences fully played are `spoken_ids`; the rest are dropped and the Phase 56 rollback
  applies. The browser no longer acks sentences.
- **Interruption rule.** The rep's speech during agent audio interrupts only when Flux
  reports a real turn start and the speech is not a backchannel ("mm-hmm", "okay",
  "right"): at least 2–3 words or a configured duration. Constants are measured in Phase 65,
  not guessed.
- **Early start.** `EagerEndOfTurn` starts NLU on the likely-final transcript; `TurnResumed`
  cancels it (the orchestrator already supports cancel-and-merge during NLU).
- **Numbers.** Aura-2 gets the same text we show; Phase 63 checks how it reads money,
  percents and dates, and adds a spoken form in `Fact.render()` only where it misreads.
- **Audit and budget.** Every STT session and TTS request is audited (role `stt` / `tts`,
  seconds or characters, cost estimate) and counted against a daily voice budget like
  `app/llm/budget.py`. This replaces the CLAUDE.md rule "all STT calls go through
  `app/llm/client.py`" for the Pipecat path; the rule is updated in Phase 63.
- **Removed in the end:** `speechSynthesis`, vad-web, `webkitSpeechRecognition`, WAV upload,
  the browser barge and echo logic, Groq Whisper for live calls (kept only if a test needs
  it).

### Execution strategy

- **Wave A:** 62 ∥ Phase 60 (engine explain/what-if). 62 adds only `scripts/` and `eval/voice/`;
  60 touches the engine, `term_alts`, the trace. No shared files.
- **Wave B:** 63 alone (server pipeline; touches `ws.py` and the orchestrator hooks, which
  60 also reads, so start 63 after 60 merges or rebase it on main).
- **Wave C:** 64 (browser; UI review).
- **Wave D:** 65 ∥ 66. 65 tunes pipeline constants and the harness; 66 adds ICE/TURN,
  `render.yaml` and the budget guard. Shared file risk: `app/config.py` only; 66 adds its
  settings in a separate block.
- **Wave E:** 67.
- Phase 61 (engine docs) can run any time after 60; it does not touch voice.
- User steps: create a Deepgram key (before 62), a Cloudflare TURN key (before 66), add both
  to `.env` and Render.

### Phase 63 — Server voice pipeline (Pipecat + Deepgram, behind a flag)

You are implementing Phase 63 (server voice pipeline) for Debt-Settlement-Agent. Read the
Phase 62 report first and follow its go/no-go changes.

1. **Pipeline** `app/voice/pipeline/`: transport `SmallWebRTCTransport` (offer/answer at
   `POST /voice/offer?call_id=…`, ICE via `PATCH`), `DeepgramFluxSTTService` (EndOfTurn,
   EagerEndOfTurn, TurnResumed; `should_interrupt` per Pipecat's guidance for STT with
   built-in turn detection), `OrchestratorProcessor` (ours), `DeepgramTTSService` (Aura-2).
   The call must already exist on the WebSocket; voice attaches to it by `call_id`. Only one
   voice session per call.
2. **OrchestratorProcessor**: on a final transcript calls the same orchestrator path the
   WebSocket uses today (`on_creditor_text`), emits the same UI events on the call's
   WebSocket (`transcript`, `say`, `turn_trace`, …), and sends each sentence to TTS with its
   sentence id. Eager end-of-turn may start NLU early; a resumed turn cancels it.
3. **HeardTracker**: a sentence counts as heard when its audio finished playing on the output
   transport. On interruption: `on_barge_in(spoken_ids)` with the fully played sentences;
   the unplayed ones are dropped (Phase 56 rollback and fragment merge apply unchanged). No
   browser acks on this path. Tests with fake transport and fake services: interrupt before
   any audio (rollback), after sentence 1 (sentence 1 heard), after all.
4. **Interruption rule** (initial values, tuned in 65): backchannel list and a minimum word
   count before a barge; documented constants.
5. **Audit and budget**: audit `stt_session` (seconds) and `tts_request` (characters, sentence
   id), cost estimate, daily voice budget (like `app/llm/budget.py`) that refuses new voice
   sessions over the cap with a clear UI error. Update CLAUDE.md: the Pipecat voice path
   calls Deepgram directly, audited and budgeted here; NLU/NLG still go through
   `app/llm/client.py`.
6. **Flag**: `VOICE_STACK=pipecat|legacy` (default `legacy` in this phase). Dependency
   justification in the commit message (`pipecat-ai` with the deepgram and webrtc extras).
7. Numbers: apply the Phase 62 Aura-2 findings in `Fact.render()` (spoken form only where
   Aura-2 misreads), with tests; the displayed text keeps today's format.

Paid cap: $5. Acceptance: unit tests for the processor, tracker, rollback, budget; the
harness from 62 runs against the new pipeline with a minimal test page or the spike client
and reports numbers; pytest, ruff, fast suite without `.env`, oracle eval PASS. Commit:
`phase 63: Pipecat + Deepgram server voice pipeline behind VOICE_STACK`.
