and [`DESIGN.md`](../DESIGN.md) can be traced to a file. Each folder is one run
(or one before/after pair) with a `summary.md` that names the command that
produced it. Per-run raw outputs under `eval/results/` stay gitignored. Summary
titles name the build phase they were made in; the phases come from the

## Policy eval (oracle / template)

Offline policy gate: FakeLLM NLU oracle, template NLG, template sim phrasing.
No API keys. CI runs the same command on every push and PR:

```bash
python -m eval.run_eval --nlu oracle --nlg template --sim-phrasing template \
  --scenarios 100 --seed 7
```

The transcripts in [`policy_eval_20261006/`](policy_eval_20261006/) predate the
agent's opening line; see its [`NOTE.md`](policy_eval_20261006/NOTE.md).

## NLU corpus

Live scoring of hand-labelled lines in `tests/nlu_corpus*.jsonl`. Every run
writes one `## <LABEL>` row in [`nlu_corpus.md`](nlu_corpus.md) and its raw
per-line answers in [`records/`](records/README.md), which can be rescored
without any model call (`--from-records`). Regenerated by:

```bash
python -m eval.nlu_corpus --label BEFORE|AFTER
```

## Live runs and free-tier daily limits

Live evals that run several arms (such as the A/B) use the free-tier providers,
and their daily caps can stall a run partway through. Gemini's requests-per-day
limit resets at midnight Pacific time (about 12:30 IST). Groq's tokens-per-day
limit is a rolling 24-hour window, so it frees up gradually rather than at a fixed
time. Start multi-arm runs just after the Gemini reset, run at most two arms at a
time (as the A/B did with `ab_20261007/providers_split2.yaml`), and finish an
interrupted run with `python -m eval.run_eval ... --resume RUN_ID`, which re-runs
only the scenarios skipped for quota.
