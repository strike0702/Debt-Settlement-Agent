# Latency, BEFORE / AFTER Phase 21 (2026-10-07)

Server-side stage timings from the WS `latency` event. Each run is 20 scripted
rep turns, `easy_deal`, demo profile (Groq `gpt-oss-120b` NLU, Groq Whisper
turbo STT), one call at a time, with 1 s of rep "think time" between turns.
Raw per-turn samples are in `latency_20261007/`.

- **BEFORE**: base commit `20f6719`, `NLG_MODE=llm` (Groq `gpt-oss-20b`), one
  token bucket per provider (capacity 1, so Groq calls are spaced 2.4 s apart).
- **AFTER**: this phase: `NLG_MODE=bank`, `(provider, model)` buckets with
  burst `min(rpm, 5)`, and the concurrent WS. Demo NLU stays at default
  reasoning effort, because the `reasoning_effort: low` gate failed (see
  `nlu_corpus.md`).
- `queue_ms` is time spent waiting on rate limits: our limiter plus Groq's short
  429 Retry-After sleeps. It is already inside `stt_ms` / `nlu_ms` / `nlg_ms`,
  so do not add it to them. It did not exist BEFORE. The "hidden wait" row
  derives it from the BEFORE audit log: stage wall time minus the LLM request
  time recorded for the same turn.

## Reading it

- **NLG is gone from the reply path.** 1.2–1.4 s p50 → 0 ms. The bank template
  is picked locally and runs through the same guards.
- **Our limiter no longer waits.** STT dropped 681 → 207 ms p50, now the same as
  its request time. Text-turn waiting dropped 2.2 s → 0 at p50.
- **Groq's tokens-per-minute cap now sets the tail.** Free tier: 8,000 tokens
  per minute per organization. One NLU call uses about 1,150 tokens at default
  effort (`nlu_corpus.md`), so about 7 calls a minute fit. The probe runs about
  15–20 turns a minute, so Groq returns 429 with a short Retry-After. The
  client sleeps and retries on the same target, and that sleep is the AFTER
  `queue_ms` p95 of about 6 s. The voice run started straight after the text
  run, while the minute window was still full, which is why its p50 queue is
  2 s. A human rep speaks for several seconds per turn, so a real call mostly
  stays under the cap. BEFORE carried the same 429s, hidden inside `nlu_ms`.
- **End of speech → first audio (voice, estimate).** VAD hangover 770 ms (was
  1540 ms), plus WAV send → first `say` 3.7 s p50 (was 5.5 s), plus browser TTS
  onset about 0.2 s. That is about **4.7 s p50, down from about 7.2 s**. The
  browser's `vad_end_to_first_audio_ms` is now stamped on `utter.onstart`, and
  the "One moment." backchannel covers the gap after 1.2 s. A
  browser-measured number is still to come (this probe has no browser).
- **Still left:** the NLU request itself (about 1.4 s p50), and Groq TPM bursts.
  `reasoning_effort: low` would cut both (p50 869 ms, about 23% fewer tokens)
  but fails the corpus gate on private-info, commitment, and hostility recall.

## Commands

```bash
# server (BEFORE = commit 20f6719 with NLG_MODE=llm; AFTER = this commit with NLG_MODE=bank)
LLM_CACHE=false NLG_MODE=bank DB_PATH=/tmp/probe.db uv run uvicorn app.main:app --port 8021
# text turns, then voice turns (macOS `say` → 16 kHz WAV)
uv run python scripts/latency_probe.py --url ws://127.0.0.1:8021 --turns 20 --out after_text.json
uv run python scripts/latency_probe.py --url ws://127.0.0.1:8021 --turns 20 --wav --out after_voice.json
# oracle-NLU variant (server with NLU_MODE=oracle)
uv run python scripts/latency_probe.py --url ws://127.0.0.1:8021 --turns 20 --oracle
```

`LLM_CACHE=false` keeps repeated script lines from being served from the
response cache. BEFORE ran on the default `GROQ_API_KEY`. That organization's
`gpt-oss-120b` daily token cap (200K) was used up partway through this phase, so
AFTER ran with `GROQ_API_KEY` set to a second key from another organization
(same free tier, same per-organization limits).
